# EvoSight 多 Agent 协作与知识库优化方案

设计草案 · 2026 年 11 月 27 日 · 对照仓库版本 `325fe6a`

建议由一个面向用户的 Codex 主 Agent 对研究结论负责。它按问题派出少量能自行查证的侦查 Agent，全组共用事件黑板。一次调查可以跨越多轮，等材料时释放计算资源，新证据到达时沿原调查线继续。RSS 等订阅由后台持续巡检，Agent 按需搜索。

每个事件保留自己的材料、分析和待查问题，并在黑板上维护一份**世界知识查阅指南**，指向可能有关的目录、实体、条目和查询。实际采用的世界知识则由事件索引记录具体版本及采用理由。

第一版从**一个事件主 Agent、一条可续接的侦查线、按需独立复核**起步。简单问题由主 Agent 直接回答。有可并行查证的问题，再增加侦查线。轮次继续作为面向用户的时间记录和历史回放边界。

## 1. 现有流程卡在哪里

| 当前行为 | 对研究的影响 |

## 2. 谁负责什么

| 角色 | 职责与生命周期 |
| --- | --- |
| **主 Agent，默认 Codex** | 用户有一个对话入口。工作区会话处理跨事件提问、主题发现和事件路由，每个事件用自己的长期主会话承接规划、分工、综合、日常复核、预测和回复。主 Agent 决定哪些成果值得入库、归入哪个目录、应关联哪些事件。 |
| **侦查 Agent** | 新闻与探索补源默认使用 DSH，其余调查线默认使用 Codex。按“事件 × 持续要回答的问题”保留身份。例如同一条“交割是否完成”的调查线可以连续几轮跟踪公司披露和监管文件。新闻、人物、机构、行业、依赖、反证作为调查角度和可选工具。问题已回答就结案，出现新证据可重开。 |
| **独立复核，按需启动** | 重大预测、方向反转或关键来源相互矛盾时，由作者之外的 Agent 在干净会话中先独评，再与主 Agent 对照。主 Agent 对最终发布负责，并记录采纳、修订或保留分歧的理由。 |
| **后台程序** | 分配身份，管理时钟、并发、预算、租约、材料归档、权限与数据库事务，维护索引并执行已经授权的操作。每次发布都能追到对应事件、目标版本和证据版本。 |

派工时主 Agent 写明要回答的问题、调查范围、已有证据、缺口、交付条件和预算，侦查员决定怎么查。同一个问题若有了负责人，后来者可以先看其进展、交接新材料或提出有理由的独立核查。Anthropic 的研究系统也把清晰分工、工具选择和交付格式作为委派质量的一部分。[Anthropic 多 Agent 研究系统实践](https://www.anthropic.com/research/multi-agent-research-system)

## 3. 黑板如何让 Agent 真正协作

每个事件一块持久化黑板。主 Agent 把总体目标拆成有稳定编号的问题。问题可以跨轮延续，每项进展都标记目标版本和记录时间。用户改变目标后，主 Agent 标出哪些问题继续、哪些要重审、哪些可以关闭。

| 黑板内容 | Agent 需要看到什么 |
| --- | --- |
| 目标与当前判断 | 用户在追踪什么、时间范围、当前判断及依据、哪种变化足以推翻判断。对反证任务显式传入待检验的判断版本。 |
| 调查进度 | 问题编号、负责人、已查范围、已排除的解释、依赖、完成条件、正在等的材料和下次唤醒条件。 |
| 证据目录 | 原始发布方、文档和片段编号、原文定位、材料版本、可用状态、发布时间和首次取得时间。同一网址的快照保留版本，转载指回原出处。 |
| 世界知识查阅指南 | 每个开放问题值得查哪些世界知识、为何相关、什么时候再查。侦查员可以补充查阅路径，主 Agent 随事件目标维护指南。 |
| 发现、异议与决定 | 每项候选结论指向证据和问题。异议指明哪一条主张、哪个字段有冲突。主 Agent 登记处理结果，核实后再提交知识库或更新预测。 |

Agent 可按问题查询黑板、订阅变化，也可定向发送“请核查这份材料”“这与判断冲突”“我已查完这段时间”。每条消息带上问题、材料和接收人，登记后按游标投递。会话恢复只补读与任务相关的变化。原文归档一次，多人可以独立阅读。两人引用同一发布方的同一材料只计一份来源。

同一主张出现相反证据时，把两份材料并列交给负责裁决的人。2026 年 11 月一项文档审阅预印本发现，在其受控实验中，多 Agent 更容易检出相互矛盾的两条材料，但当材料分散在不同 Agent 手里，最终报告更容易漏掉冲突。EvoSight 可据此做一个交接测试，让两名侦查员各读一份相互矛盾的公告，检查主 Agent 能否指出争议字段并引用双方原文。[多 Agent 证据交接实验](https://arxiv.org/abs/2611.22245)

## 4. 工具、复核与用户授权

侦查员拿到任务后可以连续执行“看已有工作 → 读原文 → 补一个查询 → 检查结果 → 提交发现或等待”。提示词交代目标、证据要求、交付和停止条件。运行时实际开放相应工具，每次返回可再次使用的材料编号、抓取状态和来源。保留已有的本地材料库和世界知识检索入口。[材料采集](../evosight/materials.py) · [世界知识检索](../evosight/world_search.py)

- **共用工具**支持查询黑板和已有知识、按编号读取材料或指定版本、搜索网页、抓取并归档原文、领取问题、交接证据和提出异议。按调查需要加配专用工具，例如公告检索、行情查询或人物公开言论检索。后台按任务限制调用数、时间和模型预算。
- **日常复核**由主 Agent 核对结论是否回答了问题，引用是否支持具体对象、时间和数值，以及同一主张是否已有相反报告。重要分歧留在黑板上，指定下一步可以裁决它的证据。每次预测保留信息截止时点、预测期限、概率、依据、反证条件与修订理由。
- **反证和独立预测采用不同输入。** 反证员需要看到原判断、理由和可证伪条件。独立复核员先看问题、截止时点、原始证据和判定标准，先提交自己的结论和概率，再看作者意见。历史回放仅提供当时已取得的材料版本。
- **对话操作绑定具体目标。** 主 Agent 将用户意图解析成操作、事件、目标任务和有效版本，后台据此核验授权并留存用户消息。取消定时任务时，先从用户指令或明确的对话上下文确定事件，再核验任务归属。范围明确就执行，有多个可能目标才用事件名或任务名澄清。Agent 间的委派消息只传递研究任务。[现有事件解析与取消入口](../evosight/workspace_agent.py#L334)

### Codex 的实际工具权限

| 任务 | 网页搜索 | 本地读取与提交 |
| --- | --- | --- |
| 查源、规划、侦查、主题发现及最新资料对话 | 可搜索公开网页、打开发布方原文，查证据缺口和反例 | 可用只读 shell 检索本轮资料。侦查员可提交原文 URL，由后台抓取、存档并返回文档和片段编号。最新资料对话可回访至多两个原文链接，保存当次实际取回的正文供引用。 |
| 综合报告定稿、预测登记和修订 | 关闭实时搜索 | 主 Agent 续接同一调查，读取本轮证据集并签发结论。出现新缺口时可在报告列出，预测也可暂缓并说明原因。 |
| 预测盲审、按登记当时解释预测、到期裁决 | 关闭实时搜索 | 独立会话读取相应证据。盲审共享作者可读的原文清单，登记时讨论读取原始快照，裁决由后台按登记来源备料。演示和显式标记为回放的输入也关闭实时搜索。 |

符合实时取证条件的 Codex 任务默认使用项目自管的 `search_public_web`。它通过本地 MCP 只接收公开检索词并返回网页链接。文章原文由后台回访和留档。现有 kprsi 的 Responses Lite 接口拒绝托管网页搜索工具，Codex 的独立搜索路径也返回 404。接入支持原生搜索的提供方时，可设置 `EVOSIGHT_CODEX_SEARCH=native`。[项目搜索工具](../evosight/web_search_tool.py)

每次调用有独立的只读资料目录。`context.json` 保存任务与黑板信息，`D编号.txt` 按文档列出归档段落、定位和片段编号。后台记录可供读取的片段编号。研究 shell 只可读本轮资料、自己的工作目录和必要的系统运行文件，命令网络关闭，审批策略为 `never`。Windows 启动时检测 MXC 进程隔离，检测失败时仍保留网页搜索和业务取证入口。个人连接器、外部 MCP、登录态浏览器、钩子、个人跨会话记忆和原生子 Agent 均关闭。调查线交接、知识发布和用户授权操作由 EvoSight 记录并执行。[工具与工作目录](../evosight/agent_tools.py) · [OpenAI 权限说明](https://learn.chatgpt.com/docs/permissions)

## 5. 长期会话怎样休眠、恢复和补做

长期保留的是调查身份、会话标识和工作进度。只有实际推理或取证时才占执行槽。用户追问、新材料到达、收到交接或核查日期到期，都可以唤醒同一调查线。

1. **首次运行。** 给主 Agent 和每条侦查线分配稳定工作目录与业务身份。使用可持久化的 Codex 会话，从 JSON 事件 `thread.started` 保存 `thread_id`。后续按明确的 ID 执行 `codex exec resume <SESSION_ID>`，同一会话的前后台请求串行。
2. **每步存档。** 工具执行或报告提交后，保存最近完成的步骤、已查证据、开放问题、下一动作、唤醒条件和黑板游标。Codex 可自动压缩上下文。结论所需的原文、版本和截止时点保存在业务库，可按编号重新读取。[Codex 非交互运行与会话恢复](https://learn.chatgpt.com/docs/non-interactive-mode) · [Codex 上下文压缩配置](https://learn.chatgpt.com/docs/config-file/config-reference)
3. **沿用会话后端。** 工作台可分别设置常规 Agent 和新闻查源 Agent 的默认后端。主会话和侦查线一旦开始，后续调用继续使用各自的后端，修改工作台默认值只影响新会话和独立调用。跨后端交接依赖已保存的问答、材料和检查点，建议同一条调查线始终使用同一后端。用户在讨论中手动切换会更新该主会话的后续选择。若切回 Codex，会尝试续接原生会话，原生会话失效时再按检查点重建。
4. **按依赖调度。** 一个槽空出就派下一件就绪任务。等待原文、同伴或配额时保存进度并释放槽。遇到紧急任务，低优先级调查可在两次工具调用之间让出执行槽。慢任务到期限先交付已核实部分，再转入等待或由其他执行者接手。主 Agent 可先发布独立成立的结论，缺少关键证据的预测留待核查。
5. **失败有人接。** 普通角色失败进入有上限、带退避的任务级重试。重试耗尽或长时间无进展时，在事件页显示负责人、最后错误和下一步。每次领取任务产生新租约版本，续租失败和恢复都留下记录。后台按租约版本核验写入，拒绝旧执行者提交。同一业务步骤有稳定的幂等键，中断后据此识别已完成的步骤，避免重复发布。

## 6. RSS 留在全局，搜索交给 Agent

| 时机 | 谁来做 | 产生什么 |
| --- | --- | --- |
| 持续盯住已知来源 | 全局巡检服务统一轮询 RSS、Atom、官方 API 和公告栏目。同一次巡检中每个来源抓取一次，各事件独立保存订阅条件和游标。 | 新条目进入共享材料目录。无更新时沿用条件请求，不唤醒模型。 |
| 研究中发现证据缺口 | 主 Agent 或侦查 Agent 主动换关键词、查历史、找原文或寻找独立来源。发现有持续价值的来源时，可建议纳入订阅。 | 在问题下登记查过什么、命中哪些原文。搜索摘要作为查证线索。 |
| 来源出现变化 | 普通条目先归档为原始材料，命中开放问题就唤醒该调查线，可能改变事件判断的信号才唤醒事件主 Agent。跨事件的新主题由工作区主 Agent 评估。 | 合并同一信号的重复通知，唤醒记录关联到原问题。 |

现有巡检已经做跨事件来源复用和条件请求。本地三个来源的历史试验中，第二轮全部返回 HTTP 304，模型调用为零。最直接的改动是细化信号去向，当前符合条件的“局部线索”和“重大公告”都可能创建研究轮次。例如，监管正文补齐只需先唤醒正在等待它的侦查员。[现有巡检与路由](../evosight/watch.py#L275) · [资料获取技术选型与条件请求试验](../README.md#资料获取技术选型2026-11-25)

## 7. 事件专属材料和共享世界知识

现有世界目录有 10 个一级目录、30 个二级目录、4 个三级目录，每个知识版本选一个主路径。2026 年 11 月 27 日 11:26（北京时间）的本地非演示库有 347 条当前记录，其中 188 条直接落在一级目录，187 条归为“分析与假设”，这 187 条中又有 129 条标为 `fact`。目录描述内容主题，`fact` 等标签描述声明性质。发布时还要单独判断这条发现在哪个范围内成立。[目录与字段定义](../evosight/world_catalog.py#L8) · [现有事件索引设计](世界知识库与事件索引.md#哪些对象相互引用)

**事件资料区**展示本事件收集的原件、实际引用的世界知识版本，以及自己的背景摘要、判断、预测依赖和调查进度。原件统一按来源和版本归档，各事件保存材料编号和用途。其他事件需要参考一次旧调查时，也能按事件调阅，看到当时的问题、判断和证据范围。

**世界知识库**保存另一位研究者可以脱离本事件的调查过程独立核对、引用的陈述。条目写清对象、适用范围、来源和可定位的原文。即使目前只有一个事件使用，只要陈述本身可以独立引用，就有资格进入世界库。

| 研究内容 | 适合共享的知识 | 适合留在事件里的材料 |
| --- | --- | --- |
| 分析与假设 | 有出处和适用条件的通用方法。第三方公开判断注明提出者、时间和来源。 | 我们对 ET5T 定价的推测、替代解释、反证条件和本轮修订理由。 |
| 价格与指标 | 对应车型、配置、市场、时点的官方价格，或带统计期、单位和口径的指标。 | 本事件的估价区间、选用某款竞品作基准的理由、已排除的别克 GL8 报价。 |
| 关系与依赖 | 注明有效时段并能回查原文的持股、任职或供应关系。 | 某次预测依赖一项政策如期生效，延迟多久需要重做判断。 |
| 背景知识 | 某地补贴政策的条文、有效期和适用对象。 | 这项补贴为什么影响本事件、具体采用哪几条、还有哪些疑问。 |
| 事实与进展 | 厂商发布公告或监管机构受理申报的可核实记录。 | 调查查到哪一步、哪份正文还在等、这次公告如何改变本事件的判断。 |

侦查员先把候选发现和引文交到黑板。主 Agent 逐项选择**仅记本事件、引用已有世界版本、给已有条目补证或订正、新建世界条目**。后台核验目标版本和证据，再保存条目及引用。一个调查轮次可以解决问题、排除干扰，世界知识新增数仍为零。

## 8. 每个事件维护一份世界知识查阅指南

指南放在事件黑板上，按稳定的问题编号编排。每一项写明**要回答什么、去哪里查、为什么相关、何时再查**。目的地可以是目录路径、实体编号、具体世界条目，也可以是一组可重复执行的查询条件。一个问题可以有几条查阅路径，多个事件也可以指向同一片世界知识。现有目录、实体、词项和类型字段检索可以复用，尚未结构化的条件交给侦查员回读原文核对。[现有候选召回](../evosight/world.py#L257) · [按路径及字段筛选](../evosight/world_search.py#L189)

以蔚来 ET5T 追踪为例。

| 研究问题 | 指南指向哪里，为什么相关 | 何时再查 |
| --- | --- | --- |
| 新款何时上市，官方公布了哪些权益？ | “事实与进展 → 科技与产品 → 产品上市”，限定蔚来和 ET5T，回读公告核对年款、配置及权益。 | 匹配的公告条目新增或修订时。 |
| 两次报价能否直接比较？ | “背景知识 → 方法与口径”，查整车购买与 BaaS 电池租用的差别，以及指导价、限时价各自包含什么。 | 出现口径不同的新报价时。 |
| 北京的补贴会不会影响实际购车价？ | “制度与政策 → 通过与生效”，按地区和有效期寻找候选，再核对车型和购买资格。 | 用户开始关注北京，或有符合条件的政策版本时。 |

事件主 Agent 建档时起草指南。侦查员可以沿指南查证，也能自行搜索并提议新增、修正或淘汰路径。目标变化时，主 Agent 重审受影响的指向，保留此前目标版本的指南，供历史回放。会话唤醒后可从上次查阅位置继续。

**空目录也能写进指南。** 如果暂时没有符合条件的政策，保留问题和筛选条件。世界条目新增或修订后，后台把匹配版本交给对应调查线，同一问题和版本只提示一次。命中首先产生候选。侦查员核对适用范围、主 Agent 决定采用后，事件索引才登记条目编号、具体版本和采用理由，可由版本回到所引原文片段。

## 9. 共享条目如何补全、更新和纠错

同一次只读统计中，326 条缺发生时间、295 条没有关联实体、336 条只有一版。三个非演示事件的最新快照中，没有世界条目同时被两个事件引用。评价这些数字时，要看材料是否给出了字段、是否有新的可靠证据、事件之间是否确实有可复用的问题。

- **分类和字段跟着证据走。** 主 Agent 按陈述内容选目录，人物侦查员也能提交政策或指标。侦查员可以为缺失字段补取原文。后台按类型校验对象、单位、统计期等适用字段，使字段值能回到支持它的片段，区分“未知”和“不适用”。分别记录事实的发生或生效时间、来源发布时间、系统首次取得时间，历史回放以当时可用的版本为准。[现有类型字段](../evosight/world_catalog.py#L64)
- **先找同一主张，再决定如何写入。** 原件指纹用于识别重复抓取。知识匹配则核对主体、所述事项及必要口径。实体优先核对登记编号等稳定标识，名称、别名与近义表达用于找候选。同一实体可以有多条不同事实。独立来源印证同一事实时补证，十月 CPI 初值被更正时订正十月版本，十一月 CPI 另建一期观测。[现有实体解析与条目登记](../evosight/world.py#L70)
- **争议、撤回和合并有可追踪的结果。** 现有补证校验已能识别试图覆盖旧字段的提议。改造后，同一对象、时段和口径下出现不相容的值时，把双方原文挂到争议记录，指定复核人。曾经正确的值注明有效期，已证实有误的陈述注明撤回原因。合并后旧条目编号指向保留的条目，具体版本仍可回读原文。通知当前引用事件复核其判断，过去的预测仍按当时冻结的引用回放。[现有补证保护](../evosight/research.py#L182) · [共享索引更新](../evosight/workflow.py#L705) · [Wikidata 对历史值与错误陈述的处理](https://www.wikidata.org/wiki/Help:Ranking/en)

| 四 · 跨事件复用与纠错 | 接入实体与主张匹配、争议裁决、撤回和合并。用两个确实需要同一事实的事件检验指南和索引。 | 两个事件能引用同一版本并各自说明用途。订正后各自收到复核提醒，合并或撤回后仍能重建旧预测所用的版本。 |

**第 34 轮，蔚来 ET5T。** 当时 6 个任务分属 5 种角色，收到的都是材料 #191、#195、#190。#191 是别克 GL8 的报价，另两份是汽车之家同一蔚来直播页的不同快照。回放应保留两个可查的快照，将它们计为一个来源，在事件里登记一个可追踪的缺口，新增零条 ET5T 价格或权益的世界事实。另设阳性对照，加入明确指向 ET5T、带生效时间的官方价格公告后，应能发布对应更新。

**第 35 轮，Anthropic 上市交割跟踪。** 新闻任务已拿到发行方交割公告 #94，负责 8-K 交叉核验的任务只拿到早期 S-1 消息 #105 和行情 #182。监管材料 #65 当时已取得申报索引，正文提取不完整。回放应让侦查员通过交接或检索取到 #94，世界条目标明发行方公告确认的部分，事件黑板保留“监管正文待核”。再模拟 #65 正文到达，检查能否只唤醒原问题、补证或登记分歧，并保留此前判断的历史版本。

**CPI 同一条目补证。** 重放现有隔离副本的十月 CPI 案例。预期同一条目升到第二版，五个字段有原文支持，覆盖地区与统计口径保持未知。读取第一版仍应看到补证前的字段。[已有 CPI 补证记录](世界知识目录与Agent检索.md#真实-agent-怎样处理一条旧指标)

**查阅指南从空目录等到新知识。** 先让 ET5T 事件保存北京补贴的查询，世界库中匹配结果为零。分别加入一项无关地区政策和一项适用政策，并重复投递一次匹配版本。预期只对适用政策提示一次，此时该政策仍是待核查候选。核查并采用后，在事件索引中能找到确切版本、依据和采用理由。

用相同的截止时间、可检索材料版本和预算比较现有流程与新方案。原始回放和后来注入的测试材料分别计分。记录关键材料到达并被正确使用的比例、误报和漏报、重复抓取数、未处理冲突数、失败恢复耗时，以及每条经复核新增结论消耗的模型调用和时间。同源快照与独立来源分开计数，有意安排的第二人复核单独记录。上述两轮的编号来自本地归档，作为改造验收样本。

对知识质量另备一组人工标注的原文，衡量事实是否正确、应提取事实和适用字段的覆盖率、证据不足时保留未知的比例、误合并率，以及有复用机会时正确引用旧知识的比例。保留检索命中率和固定版本读取测试，并检验在指定历史时点能否还原当时的答案。[已有目录与字段测试](../tests/test_world_catalog.py#L254) · [LongMemEval 对知识更新、时间推理和拒答的评测](https://arxiv.org/abs/2410.10813)

## 首版实现与单轮回放

首版已接入按事件和调查线续接的会话、共享黑板、按需查证与交接、失败调查线补做和高影响预测的独立复核。世界目录与事件专属材料分开存放。事件指南列出候选版本，研究确认后才更新采用索引；撤回、合并和字段争议保留原始记录。

2026 年 11 月 27 日用冻结的 IPO 材料完成了改前、改后各一轮回放。首次发布时两组的世界知识与事件材料都覆盖 4/6 个核查点。修复字段引文校验后，仅用原回答复验的新版覆盖 5/6 个。三道已到期二元题的平均 Brier 为旧版 0.2907、新版 0.2995。原始结果、离线修复、完整历史知识库和评分依据均保存在本机实验目录里。[本机 A/B 报告与两组入口](../.work/knowledge-ab-20261127-113330/AB对比.md)

第二轮沿用两份第一轮事件库，并把材料推进到下一交易日收盘。规划器先按用户目标冻结核查清单。综合 Agent 可回读侦查员的中间发现与既有预测理由，用原始片段写出逐项答复。发布后按快照读回实际保存的答复，区分已写入、已说明缺口、漏写、被拒，并列出调查过程中退回的提议。资料卡的发布方由档案元数据确认，其他提议逐字段保留支持材料。旧版覆盖 4/6 项，新版现场报告覆盖 6/6 项。两位侦查员都恢复了上一轮的业务检查点，主 Agent 的预测沿用了上一轮的 Codex 原生会话。同两道尚未到期的预测在续跑后分别取得 0.4498 和 0.45625 的平均 Brier。两组的原题、模型原答复、现场发布和同轮复验均有独立留档。[第二轮逐项对照与两组目录](../.work/knowledge-ab-followup-20261127/续跑对比.md)

## 交接唤醒、独立复核与阶段性交付

带原文的交接会同时保存消息、原文片段编号和发给指定调查线的补查任务。重复通知共用一次交接，同一调查线尚未开始的多条交接可以合并。调查者继续使用绑定的后端和会话。如果新材料补齐了上次的某条缺口，它可以指明旧缺口和新发现引用的片段。最终报告据此更新待查清单，原始调查记录仍能回看。研究页的「交接与退回」可以查到材料、处理状态和纳入结果的知识版本。

规划器把影响判断的核查项交给具体调查线。综合时，漏答项先用已有材料补写。对标为关键且准备确认为事实的答复，另开一次独立复核，提供各条调查线的原文。复核退回时，本版交代证据缺口，原调查者带着具体理由继续补证。与待核项有关的预测可以暂缓，并记录原因。

从调查开始计时，超过 120 秒仍有未完成工作时，研究页可先展示已完成调查的原文摘录、出处和待查问题。首份摘录需要至少一条通过校验的事实或来源声明。正式结论继续经过综合与复核，慢调用仍受各自的运行超时约束。

2026 年 11 月 28 日用上市交割案例完成一次配对回放。监管线先只拿到申报索引，再放入同一段 8-K 正文，重复通知并在提交综合前中断进程。两组都答对 2/2 项。新版恢复了原监管会话，一次补查关闭了过期缺口，一次独立复核确认了股数和类别。旧版答复引用了正文，缺口栏却仍称缺少正文。两组真实 Codex 调用分别为 3 次和 4 次。新闻动作采用固定脚本，本轮没有测搜索召回和预测准确率。[单轮 A/B 报告与两组原件](../.work/swarm-ab-20261128-103827/单轮对比.md)
