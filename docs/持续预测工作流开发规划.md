# EvoSight 持续预测工作流开发规划

2026-11-25 · 面向本地单用户工作台

本版采用一个分类的世界知识库。下文的“事件档案”“知识页面”“事件快照”均指该事件的知识索引和研究记录。原文、实体、可引用的知识条目及条目版本由世界知识库保存。事件索引按研究目标选择条目、说明相关性并固定所采用的版本。Agent 先定位内容目录和字段类型，再查候选与固定版本的原文。归档、重新规划或移出索引都保留世界知识。[世界知识库与事件索引](世界知识库与事件索引.md) · [世界知识目录与 Agent 检索](世界知识目录与Agent检索.md)

第一段交付要让用户只填事件和关注点，就能看到首版事件档案、系统选了哪些来源、为什么选，以及哪些问题还没查清。第二次打开时，首页直接回答“自上次阅读以来，哪些事实和判断变了”。后续每个模块都要能沿这条路径演示，并能从结论回到当时的原始材料。[本地工作流原图](../参考资料/持续预测Agent_新版工作流.svg)

## 设计边界

- 用户可以提供 RSS，也可以完全交给探索 Agent 找源。巡检按任务自行挑少量高价值平台，优先新闻，必要时直看最先公布结果的机构或项目。软件发布、国内公共事件和科技行业三类都要验证。
- 初始化负责历史建档。常规周期暂定六小时，最近发生的事进入本轮事实时间线。专项和反证研究可以回查历史，补证写回知识库。今天首次发现一份旧公告，可以改变今天的判断，原公告仍挂在它实际发生的时间上。
- 图中的八类 Agent 是八种可单独派发、验收和重试的研究任务。首版沿用 FastAPI、SQLite、Vue、DSH 和 Codex，默认允许两个独立模型调用并行。主机与服务的 CPU、内存余量共同决定实际并发，设置允许 1 至 4。常规网络轮询、去重、窗口判断和状态迁移由程序执行。
- 探索可在用户授权的兴趣范围内主动纳入新事件。复用共享人物、组织或新闻只建立引用。正式开启独立跟踪才占容量。AI 可以建议结束追踪，归档由用户决定。已登记的预测继续按规则核验。

## 模块一　创建事件与历史建档

**实现。** 用户手动创建和探索准入成功共用初始化入口。创建时保存事件名称、核心问题、范围、优先级、可选来源和目标版本，立即返回事件和任务编号。初始化先查已有来源目录，再用已试验的 DDGS 按实体别名和官方域名检索，回访原站验证订阅、公告栏目或官方 API。给出 RSS 时直接验证该入口，再判断还缺哪一类来源。记录候选来源的入选理由、能回答的问题、最近成功时间和失效原因。检索摘要只作线索。

**首版档案。** 围绕核心问题查起因、关键节点、相关人物与组织、已有公开争议和当前状态，给出证据与待查问题。知识首页一次列出背景、人物与组织、社会舆情、新闻与多模态、时间线、索引六个入口。某部分没有材料时，展示缺口和下次查什么。已有事件沿用原 ID、历史预测和阅读进度，通过补建任务生成第一份可用档案。

**验收。** 不填 RSS 建一个事件，当场看见初始化进度，完成后能点开至少一条已验证来源及其原文。给一个没有可用来源的案例，事件显示“待补来源”、查过的地方和重试入口。模拟中途退出再启动，同一事件只产生一份首版档案。用旧库副本迁移，逐项比对事件、证据引用、预测版本和阅读位置。

## 模块二　六小时调度、突发巡检与目标修改

| 入口 | 实现要点 | 验收场景 |
| --- | --- | --- |
| 六小时周期 | 按事件固定节拍生成轮次，冻结起止时间。按来源分别记覆盖范围与成功水位。离线跨过多个周期时按缺失区间补采，给失败来源单独重试。 | 用可控时钟跨过两个周期，其中一个源在第一轮失败。恢复后该源的缺口可见并补齐，已成功的事实在首页只出现一次。 |
| 突发巡检 | 规划器为每个事件选平台、频道或栏目，记录选择理由。建议先试每事件 1～2 个入口、每 10 分钟巡一次，均可调。不同事件选到同一入口时共享网络请求。根据来源、实质新信息、关联实体和对关键假设的影响决定仅存线索、局部研究或触发一次该事件的完整增量跟踪。 | 三类试点都能自动选平台。两个事件共用一个入口时，每个巡检周期只拉一次。一次重大公告及三篇转载只触发一轮，独立的新决定性公告在冷却期内仍可升级。回放中从条目在平台可见到入队，目标不超过一个轮询周期加一分钟。 |
| 用户修改 | 支持添加或修改目标、范围、优先级、关联事件，以及暂停和恢复。编辑提交时用版本号检查并发，立即记录重规划请求。进行中任务结束时校验目标版本，旧任务产出的有效原文可以入证据库，判断须按新目标重新评估。 | 在研究进行中连续修改两次，最后发布的计划采用最新目标。暂停后无新的常规任务，恢复立即重规划。两端同时编辑时，较早的旧表单能看到冲突及最新内容。 |

突发触发或手动刷新均保留原有六小时节拍。同一目标、同一窗口的请求合并并保留全部触发原因。若新信号出现在本轮已冻结的截止点之后，先持久入队，再开补充轮次。某个平台失效时按退避间隔重试，记录核查缺口，并允许规划器更换平台。空轮询消耗零次模型额度。

选平台时比较与该任务的相关性、是否能首发、重复转载比例和最近访问成功情况。例如软件发布可以直接盯项目发布页，国内公共事件可以盯新闻快讯并用主管机关公告核查，企业事件可以盯行业快讯和公司披露。示例只用于验收选择过程，每个任务可以换源。若两个入口长期重复相同报道，保留更快、更可靠的那个，并在事件页解释取舍。

## 模块三　前置探索与研究任务派发

**实现。** 每轮规划读取目标版本、上轮知识快照、开放预测、置顶事项、知识盲区、未解矛盾、本轮新增线索和可用额度。输出一张有优先级的任务清单。每项写明研究问题、角色、对象、可查时间范围、完成条件、所需证据及依赖。专项补史必须说明要验证哪条假设或弥补哪个空白，输出附上历史证据的原始日期和本次获知时间。

先用规则识别空轮次、到期核验、已完成任务和重复线索。需要推理的规划、资料研究和认知整理由 CANNBot 的 Kimi K3.1 Pro 承担。预测审核和核验使用现有 Codex 的 kprsi 配置。测试沿用低思考强度和快速 Codex 模型，正式运行使用 Kimi 最高强度和配置的最佳 Codex 模型、max 强度。每个角色显式登记，运行记录保存模型、强度、输入快照和用量。[当前模型配置](../README.md#模型配置)

**验收。** 同一批材料在“开放日期”和“项目成本”两个目标下，任务清单能指出不同的研究对象与完成条件。无新增、无到期待办时只记录检查结果。故意让一个角色超时，其他角色成果可用，页面标出缺失部分，重试只补失败任务。额度用尽时保留待办和核验预留。

工作台的默认调用上限是每日 1,000 次、每月 30,000 次，保留 2 次用于核验。在设置页可按实际使用量调整。以 20 个事件每天各运行四轮、每轮八个研究角色加规划、综合和预测各一次估算，每日约需 880 次。规划器按本轮会改变的判断选择角色，记录被推迟的问题及原因。[额度与预约逻辑](../evosight/db.py)

### 八类研究角色

每个角色提交结构化结果，包含它回答的问题、结论类型、引用的证据片段、时间、相反证据或限制、待查项。外部网页和附件作为材料传入，角色只提交建议，由业务层检查引用和写入权限。下面各行分别作为独立测试场景。

| 角色 | 输入与产出 | 如何判断做对了 |
| --- | --- | --- |
| 新闻与多模态 Agent | 从订阅线索回到新闻、公告或原始采访，提取逐条声明与精确引文。网页记段落，PDF 记页码，图片记原图与区域，音视频记字幕来源与起止时间。媒体不可取时保留原链接和处理状态。 | 同一决定的公告、转载和一段视频能归到一个事实。点击视频引文定位到对应片段，转录不清楚的数字保持待核。 |
| 人物 Agent | 将核心人物、相关公众人物和意见领袖消歧，维护背景、角色、带日期的立场和近期行动。公开且与事件有直接关系的家庭或利益关系附出处。对目的、压力和行为动因写成可检验的解释，列替代解释与反证条件。 | 同名人士不合并，同一人先后两次表态均可查。公开身份、本人表态及研究者的动机推测分别展示，缺乏依据的心理或家庭细节留空。 |
| 组织 / 国家 Agent | 归一企业、机构和政府部门，保存隶属关系、权限、利益、政策的适用对象与生效区间。一个国家内不同机构的立场可分别记录。 | 输入草案、正式通过和开始实施三份文件，档案保留三个状态与日期。用户能查出哪一阶段对事件有实际约束。 |
| 社会舆情 Agent | 按平台、窗口、检索口径记录可见样本量、去重规则、主要观点、意见领袖观点和代表性限制。只有取样口径相近才比较趋势。 | 注入多条同文转载，独立观点数不会同步增加。仅有新闻评论区的材料时明确标注平台和样本，样本不足时不输出总体民意比例。 |
| 关联事件 Agent | 从已有事件与实体找供应、依赖、共同原因等可能联系。写明关系方向、机制、证据、有效期及置信理由，评估哪个事件需要更新。 | 两个事件只是同提一家公司时只做交叉引用。有独立材料证明依赖才建立带方向的关系。A、B 互相关联不会造成循环调度。 |
| 专项研究 Agent | 每个任务只回答一个重要未知，写出检索范围、历史依据、仍缺的材料和停止条件。结果回填发起它的知识缺口。 | 为本轮新问题查出三个月前的公告，能修正当前档案，公告按原日期放置，并能从今天的补证记录找到它。 |
| 反证研究 Agent | 从当前判断推导可推翻它的观察，主动找独立来源，区分真正反例、弱反例与尚无材料，交回对原判断的具体影响。 | 给一组支持材料和一份相反的原始文件，产出须引用反例并说明它能推翻哪一项。查不到反例时展示查过的范围。 |
| 预测依赖研究 Agent | 读取开放预测的关键假设、指标、阈值、中间事件、观察来源和时限。将指标变化连接到受影响的题目并说明方向。 | 上游指标恶化时只让依赖它的题目进入评估，资料可以促成修订。只有触及题目预登记的结算标准才进入决定性核验。 |

### 人物名单、公开账号与增量跟踪

规划 Agent 根据主题、资料里的姓名与公开身份原文提出人选，给出关联理由。事件引用世界知识库的人物实体。相同名称可以对应不同身份。已知人物在六小时轮次轮换核查，每轮优先检查最久未查的两人；空新闻轮次也会执行。初始化或用户发起人物专项时可定向补历史。平台原帖、报道及历史材料保留原 URL、片段和时间。

人物研究先核对身份和发布方资料，再读取 X、微博、小红书的公开材料。本人发言须能从公开个人资料确认账号，并从帖子核对作者与可定位正文。账号候选、未能读取的页面和缺少精确时间的材料单列。研究者对动因的解释要列替代解释和可观察的反证。人物页展示平台覆盖和每项判断的依据，也可从事件讨论继续追问。

验收时用同名不同身份、相同正文跨平台转发、未经证实的账号、时间窗口边界及平台登录页检查归属与入库。冻结旧版事件索引后刷新新资料，两版引文都须可回看。

## 模块四　证据整理、窗口判断与结构化落盘

**保存顺序。** 抓取层保存来源 URL、发布方、原始条目标识、获取时间、内容摘要值和可保留的原件。正文、PDF 或媒体先提取为可定位的片段，记录提取器版本和原件标识。研究结果必须引用具体片段。业务层校验片段属于本次输入、时间精度、来源独立性、声明类型，以事务写入事实、关系和引用。可合法留存的原件按内容摘要值共用一份，受限材料保存可用摘要、定位信息和出处。来源失效后仍能核对当时实际保存的内容。

**提取方式。** 订阅复用现有采集器。入选的 HTML 正文交给 Trafilatura，以发布方订阅标题或核实过的正文标题校对。数字 PDF 用 pypdf 逐页取文，扫描件按需 OCR 并保留页图坐标。视频优先读取发布方字幕，对影响判断的片段再做转录或关键帧分析。文字稀少、标题混入脚本、转录失败时标明可用部分，安排针对性复核。媒体按需处理，2 核机器只做调度和轻量预处理。

| 材料情况 | 系统行为与时间显示 |
| --- | --- |
| 发生时间明确，位于本轮区间 | 使用左开右闭的区间。正好落在两轮边界的事实只属于前一轮。库内统一 UTC，页面按用户时区显示。 |
| 今日报道旧事，或只给日期、时区未知 | 分别保存发生时间及精度、首次公开时间、来源更新时间、系统首次获取时间、提交时间。原文不足以定位到本窗口时标为补证或时间待核，可派专项核查。 |
| 同源转载、相互矛盾或原文更正 | 追到共同首发，记录转载链。矛盾说法并列并关联各自证据。更正产生新版本，保存被替代版本以及会受影响的判断或预测。 |

**验收。** 用冻结样本覆盖精确时刻、仅有日期、仅更新时间、旧闻新发、窗口边界、更正、冲突与重复。所有已核实事实均可定位到原件片段，同源转载只计一条独立来源，未确认发生时间的材料进入本轮事实清单的数量为零。重放同一输入两次，事实数和用户未读数一致。抓取成功但后续模型失败时，证据仍在，分析待办可恢复。

## 模块五　认知更新、知识库索引与后置探索

**世界知识与索引版本。** 每轮先查世界知识库，再决定引用已有知识、补充证据、提出订正或创建新条目。人物、机构、地区、政策、指标、事实、舆情、关系、分析和背景分别组织。每个条目有稳定编号、带出处的不可变版本及贡献事件。事件索引固定条目版本、章节和引用理由。共享订正推动引用方生成新索引，旧索引与当时的预测继续指向原版。事件自己的目标、判断、时间线、预测和阅读进度单独保存。

**索引与下轮输入。** 维护条目目录、实体别名、证据与预测的反向引用、最后核实时间、未解问题。首版用 SQLite 的事件、实体、时间索引和别名表定位，再按词语筛选正文片段。给 Agent 的上下文先取当前结论，再取本轮变化、相关反证和有限原文片段。回看旧判断或重放旧预测时按当时快照取证。

**后置探索。** 新出现的人物、组织或事件进入准入队列。优先关联已有对象，只有独立研究价值明确、符合兴趣授权且在容量和预算内的目标才自动初始化。越界或相互矛盾的候选待确认，证据不足的候选进观察池。站内保留入选、暂缓和拒绝的理由。新对象下一轮才可再扩展。

**验收。** 两个事件使用同一份公告和同一个人物，原件存一份，两个事件能展示不同影响。打开旧快照看见旧判断，打开新快照可见变更理由。用别名能找到人物和相关证据，索引无悬空引用。重复发现同一对象只初始化一次，本轮不会递归生成更多事件。

## 模块六　预测管理、结算与复盘

| 顺序 | 实现与质量要求 | 验收场景 |
| --- | --- | --- |
| 先验已有题 | 冻结本轮证据集，按预登记的题面、期限和认可来源逐题判定。决定性证据到达时原子锁定该题，再结算和排复盘。出现可能决定结果的材料而来源失效、冲突或核验失败时，只挂起相关题的修订。提交前再次校验题目状态、核验结果和知识版本。 | 同时送到修订和正式结果，最终只结算一次。核验失败后直接重试修订请求也不能绕过检查。普通进展在核验为“尚未满足”后仍可触发修订。 |
| 创建新题 | 用户出题或研究 Agent 提名。高级 Agent 审核重要性、是否仍可预测、能否客观验证、是否重题，再正式提交。锁定问题、期限、正反判据、认可来源及宽限期。附概率、依据、关键假设、未知因素和反证条件。拒绝或弃答保留理由。 | 已有公开结果、题意含糊或缺少可核验来源的提名不能成为正式题。固定题保留用户原题。合格提名只产生一条预测和一个首版。 |
| 修订或维持 | 只给尚未锁定且未到期的题增加版本，保存旧概率、新概率、改变哪个假设、正反证及当时快照。证据只属重复或影响太弱时记录维持原因。 | 同一份转载不生成概率版本。输入改变关键依赖的证据后可以产生一版有理由的修订，两版都可从时间线打开。 |
| 结算与复盘 | 区分支持、反对、待补证、冲突和无法核验。明确决定性材料首次公开时刻，按首次公开与截止两者取早评分。复盘还原当时可见信息，分别归因为资料缺失、假设偏差、判断失准或事后外部变化，产生有适用范围与反例的候选经验。 | 冻结案例中 14:00 报 65%，15:02 首次公开结果为真，15:04 有一条尚未知情的修订，15:06 才采到公告。截止晚于 15:06 时，有效最终版仍为 65%，Brier 为 0.1225。缺少决定性材料时走宽限和复核。 |

### 中期趋势与预测力度

对于“未来第三至第六个月，对华半导体限制会加严到什么程度”一类问题，出题 Agent 登记基线、窗口起止、认可来源、三至六档由轻到重的互斥结果及其判据。用户可在固定题中指定题型、观察起点和判定规则，或让 Agent 根据问题选择。分档需覆盖无新增变化的情况，并明确以发布、通过或实施哪一项为准。

每个版本记录覆盖全部档位的整数概率、主情景、预期路径、判断信心及理由、逐项指向原件的支持与反向材料、各影响维度和改判条件。概率合计 100%，主情景属于最高概率档。旧版本能按原分布、原材料和原索引复盘。前端首页、台账、时间线和讨论均可识别主情景。

核验 Agent 等到观察窗口结束，再按登记判据给出实际档位。实际观察时点须落入窗口，决定性材料的首次公开时间可更晚。证据覆盖不足时进入待补证或复核。分级题采用归一化 RPS，二元题采用 Brier，两类各自汇总初始、提前七天及最终有效版本。用相邻档、多档偏差、发布晚于实际生效、错用窗口外证据和输入旧版讨论做验收。[ECMWF 的验证方法](https://www.ecmwf.int/sites/default/files/elibrary/2010/76164-verification-statistics-and-evaluations-ecmwf-forecasts-2009-2010.pdf)

## 模块七　下一轮队列、事件结束与归档

**研究队列。** 每条未解问题、预测假设、指标、反证条件、候选经验都记录归属对象、提出理由、指望看到的信号、复查时点、优先级和完成条件。新证据可提前唤醒有关条目。无新增的条目按复查时点再查。复盘经验初始为“待验证”，在后续独立案例中记录支持与反例，保留修改或撤销历史。

**退出条件。** 规划器针对跟踪目标提出结束依据，并列明开放预测、未解问题及可能的后续影响。用户可以选择继续观察，或停止常规追踪并归档。未回应时保留观察状态，同一结束理由只提醒一次。归档保留知识版本、证据、阅读位置、关系和原预测核验任务。用户可以恢复追踪并补查停追期间的缺口。

**验收。** 一条预测的关键假设能追到下一轮研究任务及回答它的证据。一条复盘经验可被下一条相关预测引用，也可被反例修正。对同一个结束建议分别回放“继续”“归档”和无回应，三条路径都符合上述行为。归档事件停止常规模型调用，未结算题到期仍能核验。

## 模块八　前端阅读与运行可见性

首页沿用事件卡与阅读位置，首屏展示新增事实、判断从何变到何处及下一观察点。后台跑完、原样转载或轮询成功只更新运行状态。事件页默认时间线，允许切换发生时间和获知时间，预测、修订、结算和复盘也在其中。知识页提供六个入口，支持当前版本、历史版本和证据下钻。编辑目标、查看或调整自动选择的平台、查看任务和重试在同一事件内可达。

**验收。** 用户从一条“判断改变”的首页卡片，可以在三次点击内读到引用原文或媒体位置，再返回原阅读区间。在两个事件间切换，只给明确标为已读的事件推进阅读位置。模拟零新增、来源部分失败、资料过期和历史补证，界面分别说明情况。桌面和 390 像素宽的手机上均可看六类档案、改目标、核对预测依据和处理归档建议。

## 数据接口与失败恢复

下表是建议新增的数据契约。实体名称供实现时对照，现有证据 ID、预测 ID 和阅读标记继续作为兼容入口。

| 边界 | 建议记录及最小约束 |
| --- | --- |
| 目标、轮次、任务 | 目标版本记录用户当时要追什么。轮次记录事件、目标版本、窗口、触发原因、所读快照和状态。角色任务引用轮次、角色、研究问题与输入指纹。周期按事件加时隙去重，突发按事件加信号去重，用户编辑按目标版本去重。 |
| 来源与原始证据 | 来源目录与事件订阅多对多。平台抓取状态和每个事件的消费进度分开保存，事件新加入时可以读取平台已有材料。原件记录来源、版本、内容摘要值和定位片段。 |
| 声明与知识快照 | 声明记录类别、主体、内容、时间及精度、支持与反对的片段。快照引用有版本的声明、实体、关系和章节。业务数据、索引更新和首页变化在同一发布事务落地。失败时用户继续读上一份完整版本，已完成的局部结果保留供续跑。 |
| 预测与观察项 | 预测版本引用精确知识快照、证据、模型和依赖。核验结果记录题目、本轮输入、锁定状态与结算记录。观察项和候选经验能反查到发起的预测或复盘。 |
| HTTP 与前端 | 扩展现有创建入口，新增目标编辑、知识快照与差异、研究轮次、结束建议响应等读写接口。长操作立即返回任务 ID，目标编辑带预期版本，知识查询可指定历史快照，冲突返回可显示的当前版本。 |

建议首先固定三个接口。现有 `POST /api/events` 接受空订阅数组并返回初始化任务。拟新增的 `PATCH /api/events/{id}` 接收目标改动和 `expected_version`，成功返回新目标版本和重规划任务，过期返回 409。拟新增的 `GET /api/events/{id}/knowledge` 接受章节、当前或历史快照及可选的比较版本，返回变化、逐条引文和未核实项。开发时先用这三个接口贯通表单、后台和知识页面。

长耗时联网与模型调用放在数据库事务之外。已落盘的角色结果按输入指纹复用，发布操作用事务和唯一键保证一次生效。若远端已收到请求、本机还没保存结果就断电，记录这次调用状态待核，用原预算记录决定是否重试。来源的检查结果和原始材料保存成功才推进该源水位。研究在知识快照发布后推进，阅读位置在用户标记已读后推进。运维页按轮次给出耗时、模型调用与预算、来源覆盖、失败角色及重试结果。

## 人机讨论与预测解释

全局对话复用事件讨论的模型后端、知识引用、任务队列及回执。从工作台可查看跨事件进展，按事件名、简称或编号调度。事件页和预测版本提供默认上下文。用户可以创建事件、修改目标和周期、编辑长期收集范围，以及立即运行、预约单次运行或取消预约。对含多项操作的一条指令，服务端核对用户原话、事件版本、定时时间和工作区状态，在一个事务内保存修改与任务。事件指代有歧义时，支持用户回复一个名称或编号继续。成功回执带操作前后值，关联事件、轮次及任务。测试从空库创建，覆盖旧讨论迁移、重名、并发修改、重放、时区和定时取消。[全局调度回归](../tests/test_workspace_agent.py)

在当前活跃事件的讨论中，用户可以明确要求持续收集一个人物或事项。讨论 Agent 从本轮用户消息中提取对象、关注点及授权原句，服务端核对后在同一事务内登记收集要求、首次核查轮次及对话回执。重复提交沿用既有任务，已冻结输入的在途轮次之后单独补查。用户指定的人物和事项每轮都会检索并记录覆盖情况，包括零新增和检索不可用。首次可以补历史，常规更新按事件窗口收录。人物身份、社交账号归属及共享知识条目继续按公开材料核对。可从相关人物及研究页查看进展。[收集范围实现](../evosight/focus.py) · [跨周期验收](../tests/test_focus.py)

事件页提供持续讨论，概率历史的每一版有独立入口。用户提问时，系统冻结事件目标、索引版本、与问题相关的世界知识条目、证据及同一范围最近六轮对话。事件索引内按主体与内容匹配问题，最多取十二个条目，并为条目附上可定位的引文。预测版本直接关联产生它的成功调用，保存原输入、结构化结论、模型和思考档位。早期数据仅在事件、时间、题目、概率、理由和证据等记录可唯一对应时恢复调用关联。

预测复盘分两个资料范围。登记当时只载入该版本的原记录和当时的事件索引。结合最新同时保留原记录，并载入提问时的索引、时间线与新裁定。模型输出公开依据、反例及信息缺口。每条引用在服务端对照本轮材料校验。用户可跨 Codex 和 dsh 追问，双方从相同的结构化归档恢复讨论。正式预测沿用既有修订流程。

**验收。** 能从一个概率版本打开原预测输入，追问概率依据，再切换后端讨论同一假设。事件更名、世界条目更正、暂停追踪及服务重启后，已发送问题的资料范围保持固定。覆盖原始归档缺失、跨事件版本、重复提交、未知证据、额度预留、失败重试与回答返回后进程中断。[讨论回归](../tests/test_discussion.py)

### 端到端验收方法

1. **建立可重放的材料包。** 软件发布用现有 Vue 发布事件。国内公共事件选一个有主管单位公告的事件，科技行业选一个有公司公开披露的事件。三类都保存当时的订阅或页面、来源独立性、期望发生区间、重大信号和应受影响的事件。真实联网验证可访问性，固定样本验证结论和重复执行。
2. **跑完一次完整生命周期。** 用虚构的市域线开放事件，依次注入初始档案、旧闻转载、历史反证、途中修改目标、决定性公告和稍后到达的转载。逐步断言首页变化、知识版本、预测冻结、评分、经验待办、归档后核验。把时钟拨回前一轮时，只能查到当时可见的资料。
3. **验证质量与成本。** 样本内逐条核对所有重要事实、人物立场、预测及结算的证据定位和时间归属。记录漏报和误报，特别核对“重要公告漏触发”“窗口外旧闻当新事”“转载重复触发”。空巡检的模型调用数必须为零。每轮显示调用明细，配置的日月上限与核验预留在重试时也生效。
4. **验证可恢复与可用。** 在抓取、模型返回、发布三个位置分别中断进程并恢复，对比发布次数、旧快照和阅读位置。在目标机器运行 24 小时，覆盖四个常规周期并插入突发和用户编辑。记录内存峰值、队列等待及首页查询延迟，要求无内存耗尽、无丢失待办、无重复结算。沿用已有采集与工作台回归，并加入本规划的跨模块场景。[现有采集测试](../tests/test_rss.py) · [工作台回归](../tests/test_workbench.py)

产品已确定常规周期、按任务选平台、专项可补史，以及归档需用户决定。每任务巡检来源数、巡检间隔、冷却时长和角色并发按实测调整。首次调参以三个试点的重大消息延迟、重复触发次数、来源可用率和每事件调用量为依据。
