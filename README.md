# EvoSight

EvoSight 是本地单用户事件研究工作台。首页回答“我上次读完后，关注事件的事实、判断和下一观察点发生了什么变化”。每条记录都能回到原始材料、概率版本和裁定依据。

所有真实事件共同维护一个分类的世界知识库。Agent 可以按内容定位目录、查字段定义，再按版本取原文。每次预测固定当时的事件索引。[世界知识目录与 Agent 检索](docs/世界知识目录与Agent检索.md) · [世界知识库与事件索引](docs/世界知识库与事件索引.md) · [持续预测工作流开发规划](docs/持续预测工作流开发规划.md)

## 在当前 Windows 电脑上运行

在仓库目录执行下列命令，然后打开 [本地工作台](http://127.0.0.1:8765/)。

```powershell
if (Test-Path .\.work\media-tools\enable.ps1) { . .\.work\media-tools\enable.ps1 }
.\.venv\Scripts\python.exe -m evosight serve --mode live
```

首次启动时工作台为空。可以从首页新建追踪，也可以在全局 Agent 对话里指定事件和研究目标。后续启动会续用本地数据库。

`--demo` 添加两条相关的虚构交通事件，用于体验共享来源、两轮判断、概率修订和已结算案例。演示事件跳过自动追踪。主动向演示事件提问会调用所选模型。评测页单独统计真实题。重复启动会保留原先的数据。

## 跟踪相关人物

打开事件里的 **相关人物**，可以查看每个人与事件的关系、身份原文、公开账号、带日期的材料，以及写入世界知识库的分析。人物名单由研究目标和具名材料生成，事件引用共享人物实体。已有事件在恢复研究后也可以建立名单。

常规六小时轮次会轮换核查人物。页面把本人公开发帖、转发、媒体报道、历史材料和归属待核的线索分别标注，并列出每个平台本轮查到了什么。点 **补查人物与往事** 可以补充较早的采访和往事。账号的归属可根据页面所列出处人工确认或排除。

X 支持公开帖子嵌入。在服务进程配置有相应读取权限的 `EVOSIGHT_X_BEARER_TOKEN` 时，还会读取已核实公开账号在窗口内的时间线。微博和小红书使用公开检索、账号页及具备作者和正文的公开帖子。来源只返回登录页、账号归属不明、没有可用发帖时间时，界面会显示相应缺口。[X 用户时间线](https://docs.x.com/x-api/posts/timelines/introduction) · [X 公开嵌入](https://docs.x.com/x-for-websites/oembed-api)

## Agent 并发与资源

进入 **设置 → Agent 最大并发** 可选择 1 至 4，默认 2。**运行记录** 显示配置值、当前允许并发、正在调用的数量与可用内存。两核主机最多同时运行两个模型调用，可用内存下降或 CPU 持续繁忙时自动收紧。调度器按每个 Agent 320 MiB 估算，并为系统预留 320 MiB。

同轮的独立调查线可以并行，一个执行槽空出即可派下一项。主 Agent 按事件延续会话，侦查 Agent 按调查线延续会话，同一会话的请求串行。轮次综合后，失败的调查线可按任务单独补做。模型名额、日月额度及核验预留在同一数据库事务内分配。

## 分级趋势预测

在事件的 **相关预测 → 登记固定题** 输入问题，选择 **由 Agent 按题意选择** 或 **分级趋势与力度**。点 **观察未来第 3 至第 6 个月** 可填入对应的日历起止时间。给出认可来源和什么算观察结果，Agent 会根据材料设计三至六个有序档位。

例如研究对华半导体出口限制，可把维持或放宽、定向收紧、扩大适用范围、更广泛收紧分别定义为可从正式公告判定的结果。预测页展示每档概率和判据、主情景的预期路径、判断信心、支持与反向证据、影响维度和改判条件。观察窗口与分档在登记时固定。此后每次修订都保留完整分布和所据材料，可以点进历史版本与 Agent 讨论。

等完整观察窗口结束，核验 Agent 根据认可来源登记实际档位、观察时点、证据首次公开时间及依据，也可给出证据不足或冲突。评测台账单列分级题的归一化排序概率评分（RPS），相邻档比跨越多个档位的判断偏差小。[评分定义与依据](https://www.ecmwf.int/sites/default/files/elibrary/2010/76164-verification-statistics-and-evaluations-ecmwf-forecasts-2009-2010.pdf)

## 和 Agent 讨论

左侧的 **全局 Agent** 汇总真实事件的讨论和执行记录。可以直接说「新建事件上海车展，关注新车发布」「把蔚来事件的跟踪周期调成每两小时一次」或「给蔚来安排明天下午三点采集一轮」。Agent 也能修改研究目标、名称、优先级或人物关注点，暂停及恢复事件，安排专项核查，取消尚未运行的定时采集。指定时间按浏览器时区计算，回复可打开对应的事件、轮次与任务。[打开全局 Agent](http://127.0.0.1:8765/#/agent)

从事件或预测页进入时，可以用「这个事件」指代当前对象，也可点名另一事件。直接从全局入口追问可承接上次操作的对象。有重名时，选定具体事件后再执行。同一条指令的多项修改一并保存，重复提交会返回原回执。

在正在跟踪的事件里，可以直接对 Agent 说 **把李斌加入本事件，以后每轮都跟踪他的公开动向**，也可以指定某个事项。后台保存收集要求，立即排入首轮核查，后续沿用该事件的周期。回复会显示任务轮次；在 **研究与目标 → 持续收集范围** 可查看每项最近的核查结果，也可暂停。指定人物会立即出现在 **相关人物**，身份核实后可打开带出处的人物档案。

在事件页点 **和 Agent 讨论**，可以问近期进展、舆情或证据缺口。系统带入事件目标、提问时的知识索引、相关条目的固定版本、原文片段、近期时间线和已登记预测。点 **相关预测 → 概率历史 → 讨论这版概率**，可以针对某一次判断追问。**登记当时** 和 **结合最新** 各自保留讨论记录。回答中的引用可打开具体材料、引文位置、知识版本或概率版本。

全局讨论续接工作台主 Agent。事件讨论和按最新资料讨论预测共用事件主 Agent。按登记当时讨论预测会单独打开历史快照。三个入口都可以在记录区内滚动，用 Enter 发送、Shift + Enter 换行。新会话默认使用 Codex，也可显式选择 DSH。开始后建议沿用已选后端，以保留原生会话上下文。手动切换后，该主会话后续沿用新选择，交接依靠已保存的问答、材料和检查点。已入队的提问及重试沿用提交时选定的后端。讨论共用工作台的调用额度和核验预留。

Codex 在查源、侦查和最新资料讨论中可调用 EvoSight 的只读 `search_public_web`，由后台回访并归档选中的原文。模型继续使用配置的提供方。接入支持 Codex 原生搜索的提供方时，可在启动工作台前设置 `EVOSIGHT_CODEX_SEARCH=native`。报告定稿、预测登记、按登记当时讨论、盲审及到期裁决使用指定证据集。Windows 通过 MXC 隔离检测后开放只读研究 shell。[按任务划分的工具权限](docs/多Agent协作与知识库优化方案.md#codex-的实际工具权限)

有归档的预测可展开查看原始结构化输入和登记理由。早期或人工版本使用保存下来的概率、判定规则、引文和书面理由。讨论中的情景推演保存在对话记录中。正式修订仍从概率历史登记。[开发规划](docs/持续预测工作流开发规划.md) · [真实讨论验收](docs/工作流初版验收记录.md#人机讨论)

## 首次安装

运行需要 Python 3.11 及以上、Node.js 22.12 及以上和已配置的 Codex CLI。新闻侦查默认使用 DSH，需要 DSH 和 CANNBot 配置，也可在设置中切换为 Codex。本机用 Windows 原生 Python 3.14 和 Node 24 完成联调。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Push-Location frontend
npm.cmd ci
npm.cmd run build
Pop-Location
.\.venv\Scripts\python.exe -m evosight serve --mode test --demo
```

FastAPI 同时提供静态页面和 API。开发界面时，可在另一个终端的 `frontend` 目录运行 `npm.cmd run dev` 使用 Vite 热更新，其 API 代理指向 8765。服务和 worker 在同一进程内运行，关闭终端会停止调度。SQLite 数据默认放在 `data/evosight.sqlite3`。可用 `--data` 选择另一个数据目录，用 `--port` 更改端口。

Linux 服务器的运行目录、发布、热更新和回滚流程见 [Linux 服务器发布](docs/Linux服务器发布.md)。

## 模型配置

| 后端 | 测试模式 test | 正式模式 live |
| --- | --- | --- |
| Codex（默认） | gpt-6.2-sol · low | gpt-6.2-astra · max |
| DSH（可选） | dashscope/kimi-k3.1-pro · low | dashscope/kimi-k3.1-pro · max |

`serve` 默认采用 live。**设置 → 新建新闻侦查 Agent 默认后端** 默认是 DSH，可切换为 Codex。其他新会话默认使用 Codex，可在同页单独配置。已有主会话和侦查线继续使用各自选定的后端。研究实验可设 `EVOSIGHT_RESEARCH_BACKEND=codex` 或 `dsh`，在查源、发现、规划、侦查与综合首次建立研究会话时指定后端。

Codex 以 `codex -p kprsi` 配置运行，`EVOSIGHT_CODEX_CLI` 可指定可执行文件。当前 KPRSI 配置下 Codex 原生网页搜索不可用，可用 EvoSight 搜索。两种后端共用任务队列、租约、重试、黑板和工作区管理。工作台数据库分别保存 Codex 和 DSH 的原生会话 ID，以及应用检查点。工作目录和 DSH 持久状态都在数据目录下的 `agent-workspaces`，各自的原生进程可按需退出和续接。

DSH 加载本机 `~/.dsh/profiles/desktop/cordis.patch.yml` 中的 CANNBot 配置，Windows 默认从 `D:\DSH` 启动。其他安装位置可设 `EVOSIGHT_DSH_DIR`，也可以通过 `EVOSIGHT_DSH_CLI` 指定可执行的 headless 程序，通过 `EVOSIGHT_DSH_PATCH` 指定本地配置文件。

允许联网的 DSH 任务优先用内置 `web_search`，缺少目标来源时可用 EvoSight 搜索补查。内置搜索使用 DeepSeek 凭据，来自启动环境的 `DEEPSEEK_API_KEY` 或本机 DSH 已保存的凭据。DSH 可以搜索并回读当前任务已授权的完整归档片段，引用校验仍使用归档原文。

事件知识页展示查阅指南、候选版本和事件专属材料。侦查员可主动查本事件的归档、世界知识或公开来源，并向同伴交接。主 Agent 决定候选是否进入世界目录。固定预测、分级预测及修订会留下独立复核记录。详见[多 Agent 协作与知识库优化方案](docs/多Agent协作与知识库优化方案.md)。

## 从一条事件开始

1. 点击“新建追踪”，输入事件和研究范围即可。RSS / Atom 选填。创建后直接进入“研究与目标”，能看到入选来源、理由、轮次和任务进度，以及失败和缺口。该页也可以修改目标、选择巡检入口或发起专项研究。
2. 打开“世界知识库”按类别或别名检索，查看原文、修订历史和引用条目的事件。打开某个事件的“事件知识索引”，按背景、人物与组织、舆情、新闻、时间线或索引查阅。可引用已有知识、填写理由、移出引用或带引文订正共享条目。版本选择器支持回看当时的索引和依据。
3. 常规轮次默认每六小时一次。每事件默认选两个平台、每十分钟巡检，共用平台只轮询一次。重大新公告会提前触发整轮，另有局部线索和仅留存的线索。六小时节拍独立运行。专项与反证可回查旧公告，历史补证保留发生日期和本次获知时间。
4. 再次打开“关注动态”，可以看到自上次阅读以来的新事实、判断变化和下一观察点。点击未读条数展开这个范围，再点“读到这里”保存位置。见证据时可打开页面留存的段落、PDF 页码或发布方字幕时间码。
5. 在“相关预测”查看固定题、概率版本、引用和判据。结果先核验，再决定是否修订。二元题按决定性公告的首次公开时间与截止时间两者取早评分。分级题按完整观察窗口核对实际达到的档位，保留观察时间与公告时间。复盘经验可在独立事件中用新材料复核。结束建议由用户选择继续或归档，归档后未结算题仍按期核验。
6. 在“探索中心”设置兴趣主题和关键词，选择是否允许持续发现。满足兴趣授权、容量与额度的候选可以进入初始化队列。

设置页保留每日、每月模型调用上限及核验预留。新工作台默认为每日 1,000 次、每月 30,000 次，最后 2 次留给核验。额度按 UTC 归日、归月，保存较高上限后，原来等待额度的问题会自动继续。每次已发出的请求计一次，实际费用以供应商账单为准。核验页按初始、提前 7 天和最终有效版本分别计分。二元题使用 Brier 分数，分级题以有序概率评分（RPS）衡量所有档位的概率与实际结果的距离。迟交、无法核验和固定题弃答单独记录。

## 资料获取技术选型（2026-11-25）

常规追踪优先使用发布方的 RSS、Atom 或官方 API。搜索负责发现来源和补充缺失证据，新闻原文负责核实事实。高频监控只轮询选定的平台，将去重后可能影响事件的信号送给模型。

新事件可以不填 RSS。如果目录与搜索都没有提供可用入口，探索 Agent 根据事件主体提出发布方和替代查询。采集器回访候选地址，核对内容后再将来源纳入跟踪。Anthropic 股票跟踪同时读取公司公告、SEC 申报索引和两家发布方的交易日行情。日线按证券、交易日与发布方保留原表，申报受理时间和行情日期分开记录。

| 环节 | 选型 | 当前状态 |
| --- | --- | --- |
| 无 RSS 建档 | 从小型发布方目录和 DDGS 检索候选，回访原站识别订阅、公告栏目或文章。可补查失效来源。 | 事件和主题共用找源入口，三类真实案例均已取到原始材料。[DDGS](https://github.com/deedy5/ddgs) |
| 订阅与增量 | 借鉴 Horizon 的 feedparser 解析、条目标识和日期处理。 | 平台共享 HTTP 条件请求，各事件单独记录消费位置和窗口覆盖。缺失窗口可单独补采。[feedparser 条件请求](https://feedparser.readthedocs.io/en/latest/http-etag/) · [Atom 条目标识](https://datatracker.ietf.org/doc/html/rfc4287) |
| 原文和附件 | 使用 Trafilatura 处理新闻，pypdf 逐页取文，保留原件摘要值、提取器、引用文本和位置。 | 支持网页、PDF 和发布方字幕。图片、扫描 PDF、无字幕媒体支持可选本地工具，处理失败会显示待核原因。[Trafilatura 接口](https://trafilatura.readthedocs.io/en/latest/usage-python.html) · [pypdf 文本提取](https://pypdf.readthedocs.io/en/stable/user/extract-text.html) |
| 共享巡检 | 规则判断相关性、公告类型和转载，按事件和实质变化分配研究。 | 空轮询消耗零次模型额度。平台的访问失败、退避和已安排的补查可从事件页查看。 |

**时间与证据。** 每轮首批选取最多 12 份相关材料，专项可以补充。订阅的发布和更新时间用于筛候选。事实须由原文中的发生时间支持，窗口左开右闭。仅有日期或缺少时区时，页面保留相应精度。旧公告、更正和新事实各自记录。旧库原有预测、裁定、证据引用和阅读位置随数据库保留。

**可选媒体工具。** 图片识别使用 Tesseract，扫描 PDF 还使用 Poppler 的 `pdftoppm`。用 `EVOSIGHT_OCR_LANG` 指定已安装的语言包，例如 `chi_sim+eng`。视频优先读取发布方字幕。配置 FFmpeg、`whisper-cli` 和 `EVOSIGHT_WHISPER_MODEL` 后，无字幕音视频可生成标有“自动转写”的时间段，多语言模型默认自动判别语种，也可设置 `EVOSIGHT_ASR_LANG`。视频缺少音轨或未取得可用转写时，系统会对关键帧做 OCR。原图区域、扫描页码、视频时间和出处随片段保存。

**本机样本。** 用独立 SQLite 库对中新网社会新闻、国家统计局最新发布和 Vue 官方 Releases 各取两遍。首轮分别读到 30、499 和 10 条，第二轮三个来源都返回 HTTP 304，模型调用为 0。统计局订阅约 4.5 MB，499 条都只提供粗粒度日期，Vue 订阅的 10 条只提供更新时间。另用 DDGS 对统计局和 GitHub 各做一次站点限定查询，各取回 3 个目标域名结果。两篇中文原文都能提取到正文，其中统计局页面的自动标题混入了 JavaScript，标题应优先采用已经核实的发布方订阅或正文标题。这些结果来自 2026-11-25 的单次选型试验。[中新网订阅目录](https://www.chinanews.com.cn/rss/) · [国家统计局订阅目录](https://www.stats.gov.cn/wzgl/rss/)

可单独检查某个来源的条目数、时间精度和 HTTP 缓存支持。该命令直接读取公开订阅，不启动模型或写工作台数据库。

```powershell
.\.venv\Scripts\python.exe -m evosight check-feed https://www.chinanews.com.cn/rss/society.xml --recheck
```

Horizon 的许可随代码保存在 [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt)。
